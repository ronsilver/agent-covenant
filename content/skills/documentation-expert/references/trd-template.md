# TRD Template

## TRD-[YYYY]-[NNN]: Title
| Field | Value |
|---|---|
| Status | Draft / Review / Approved |
| Author | @handle |
| Date | YYYY-MM-DD |

### 1. Summary
One paragraph: what, why.

### 2. Problem Statement
- Current state + pain point (quantified)
- User story: "As a [role], I want [X] so that [Y]"

### 3. Evidence
- Logs/metrics, user reports, business impact

### 4. Scope
**In**: feature A, feature B
**Out**: feature C (future), feature D (separate TRD)

### 5. Proposed Solution
Technical approach with architecture diagram.

### 6. Alternatives Considered
| Alt | Pros | Cons | Rejected because |
|---|---|---|---|

### 7. Design
- Components, data model changes, API changes

### 8. Implementation Plan
1. Phase 1: description + effort estimate
2. Phase 2: description + effort estimate

### 9. Testing Strategy
Unit, integration, E2E, perf targets.

### 10. Rollout Plan
Feature flags, canary %, communication plan.

### 11. Rollback Plan
Exact steps, data recovery, monitoring checks.

### 12. Success Metrics
- Metric A: current X -> target Y
