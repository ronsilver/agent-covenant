# IEEE 1028 Review Framework

## Inspection Process (Formal)
1. **Planning**: define scope, select reviewers, schedule
2. **Overview**: author presents context (optional)
3. **Preparation**: reviewers study artifacts individually
4. **Inspection Meeting**: log defects, NEVER discuss solutions
5. **Rework**: author fixes identified defects
6. **Follow-up**: moderator verifies fixes

## Efficiency Metrics
| Metric | Informal Review | Formal Inspection |
|---|---|---|
| Defect detection rate | <50% | 60-65% |
| LOC/hour | 500+ | 200-400 |
| Meeting overhead | None | 1-2 hours |

## Role Assignments
| Role | Responsibility |
|---|---|
| Moderator | Facilitates meeting, keeps on track |
| Author | Presents code, answers questions |
| Reviewer(s) | Find defects, NOT solutions |
| Recorder | Logs all findings |
| Reader | Paraphrases code during meeting |

## Defect Classification
| Severity | Example | Action |
|---|---|---|
| Critical | Security hole, data loss | Block merge |
| Major | Logic error, missing validation | Must fix |
| Minor | Performance issue, unclear name | Should fix |
| Trivial | Typo in comment, style | Optional |

## When Formal vs Informal
- Formal: security code, critical business logic, auth systems, compliance-critical
- Informal: utility code, internal tools, non-critical features, small changes (<50 LOC)
